# 拾词 AI 说明

AI 在拾词里只是“需要时才用的帮手”，不在学习主流程里，也没有聊天窗口。背词、复习、标记、选读都不依赖 AI，断网也能用。

## 入口

| 位置 | 作用 | 用的是哪种 AI |
| --- | --- | --- |
| 阅读 → 语境记忆 | 从当天的词里自选单词，生成一篇短文；短文保存在这里，随时回来读 | 内置 AI，或你自己的 API Key |
| 学习 → “复习计划”面板 → “读短文” → “生成本组短文” | 用当前这一组单词写一篇短文，读完回到自测 | 内置 AI，或你自己的 API Key |
| 阅读时点单词 → “翻译本句”“语境释义” | 一句话的译文、单词在这句里的意思 | 内置 AI |

0.4.0 到 0.4.2 里的全局“AI 助手”（聊天窗口）在 0.4.3 去掉了，阅读页的“AI 助读”面板、逐段“AI 解析”、全文 AI 翻译和单词详情里的“AI 生成联想”也都不再有。全部 11,427 个考试词已自带助记，没有助记的词就不显示，可以自己写。

## 额度

内置 AI 由 Wordflow 云端服务代理，使用服务器上的密钥，不在 APK 里。

- 每台设备每天 60 点，北京时间 0 点刷新。翻译本句或语境释义 1 点，生成一篇短文 5 点。
- 设备用一个匿名随机 ID 计数（`wordflow.ai.device`，不含个人信息）。同一个 IP 另有 5 倍的总上限，用来挡住反复重装刷额度。
- 请求失败会退回点数。超额时服务器返回 429，应用显示“今天的 AI 次数用完了，明天再来”。
- 句子翻译、语境释义的结果在服务器缓存，命中缓存不扣点。
- 服务器用环境变量 `AI_DAILY_LIMIT` 调整每日点数。

## 速度与模型

服务器默认用资料库流水线的网关和模型（`cline-pass/deepseek-v4.1-flash`）。它是会先“思考”的模型：翻译一句话要 3 到 5 秒，写一篇短文要 30 到 60 秒，其中 80% 以上的输出是看不见的思考，关闭思考的参数无效。

要变快，给应用单独配一个不思考的模型：在服务器上创建只有 root 能读的 `/etc/wordflow/app-ai.env`，写入 `READING_AI_KEY=你的 DeepSeek 官方 Key`，再 `sudo systemctl restart wordflow-cloud`。此时默认用 `https://api.deepseek.com` 的 `deepseek-chat`，可用 `READING_AI_BASE`、`READING_AI_MODEL` 改，网关限定用 `READING_AI_GATEWAY_ONLY`。资料库流水线仍用原来的 `library.env`，不受影响。没有这个文件时行为不变。

## 网络不稳时

手机请求在几秒内就失败（连接断了、域名解析失败）说明请求根本没到服务器，应用会自动重发最多两次，再提示“连不上内置 AI，请检查网络后重试”。已经等了很久才失败的请求不会重发，免得重复扣点。

## 自己的 API Key

“我的 → AI 服务”可以填写 DeepSeek、OpenAI 或通义千问的密钥。它只用于生成语境短文：填了之后短文不占内置额度，费用由服务商收取。密钥保存在手机上（原生加密存储），不进备份。查词始终使用内置 AI。

## 发送了什么

- 翻译本句 / 语境释义：那一句话和被点的单词。
- 短文：所选单词和释义。
- 不发送：整本词库、标记、复习记录、昵称和头像。服务器不保存内容，只记录额度计数。

## 接口

`POST /v1/ai/chat`（只接受应用自身的来源）。应用只用其中的一次性任务：`{ "device": "匿名设备 ID", "task": { "type": "sentence", "sentence": "…" } }` 或 `{type:'word', word, sentence}`，返回 `{reply, model, remaining}`。服务器仍保留自由对话的 `messages` 写法，但应用不再使用。

`POST /v1/ai/reading` 的短文模式（`mode: 'story'`）计 5 点并返回 `remaining`。旧模式（导读、全文翻译等）只为没升级的老版本保留。

客户端统一在 `src/ai.ts`，服务端在 `cloud/wordflow_cloud.py`，测试在 `tests/reading_ai_test.py` 和 `tests/ai.test.ts`。
