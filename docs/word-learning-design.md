# 拾词单词记忆模块设计

日期：2026-10-01

状态：0.2.0 在既有背词流程上接入独立单元任务与语境记忆，已于 2026-10-01 发布 versionCode 11 安装包和配套 v3 云端服务。

0.2.1 本地预览完善任务数量、完成进度、复习续学与空状态。参考炭炭在[应用商店的开发者介绍](https://app.mi.com/details?id=com.maimemo.momolist.android)中强调的清晰复习安排与简单交互，保留拾词自己的实际到期规则和液态玻璃界面。

0.2.2 将主导航统一为“学习 / 词书 / 阅读 / 我的”。学习页只呈现当前任务、词组与“看词 / 读短文 / 自测”三种操作；释义核对在提交之前，重新开始和撤销放到次要操作区。阅读默认英语选读，自选词短文明确属于自由阅读。设置按用途分组，从学习中进入 AI 配置后可返回原组。视觉节奏由 `src/page-flow.css` 统一，继续复用已有玻璃材质。

目标是让用户知道自己正在学哪批词、为何复习，以及何时才记录结果。沿用列表背词、遮义自测、六点标记与原词书分组；界面将 Day 明确改为“单元”，日历日期仅用于统计与实际复习安排。

## 改造前基础与本次调整

| 改造前 | 本次调整 |
| --- | --- |
| Day 按学习单元序号回看旧 List，到期复习另按单词时间安排 | Day 组织新词；正式复习统一按实际到期时间生成；旧 Day 可自由练习 |
| 通过最近标记时间推断本轮是否忘记 | 独立保存当次结果，详情中调整标记不生成复习成绩 |
| Day 已持久化，组内位置和部分交互状态留在组件中 | 保存任务词表、组内位置及未提交结果，重启后恢复 |
| 到期队列取当前词书中的单词 | 对个人词库中已开始学习且未标熟的词统一复习，按词条 ID 去重 |
| 词书完成记录会随重新标记而清除 | 分别记录首次学习事实、当前任务进度和下次到期时间 |

实现入口为 [学习状态校验](../src/study-state.ts)、[任务业务逻辑](../src/study.ts)、[学习页](../src/StudyList.tsx) 和 [应用保存协调](../src/App.tsx)。行为回归见 `tests/study.test.ts`、`tests/learning.browser.spec.ts` 与 `tests/android-learning.ts`。

## 概念与数据含义

| 概念 | 含义 |
| --- | --- |
| 词条 | 英文、释义、音标、例句与来源；多本书可以引用同一词条 |
| 词书计划 | 词序、Day 分组和学习位置；已有计划不因标记或标熟而重排 |
| Day | 词书中的学习单元，与日历日期分开 |
| 今日任务 | 尚未完成的学习、实际到期的复习以及用户准备学习的新词 |
| 六点标记 | 用户对难词的关注程度，显示范围为零至六级 |
| 当次结果 | 本轮暂未确认、忘记或提交时确认记住的结果 |
| 熟词 | 用户主动移出学习队列的选择，可以恢复并保留历史 |
| 学习记录 | 已发生的自测及其时间、结果；首次学习事实与当前是否忘记分开 |

一个词可以同时具有“学过、六点标记、今天到期、本轮忘记”这些状态。一次记住保留原有标记；用户仍可自行降低标记。历史大于六次的原始值继续兼容，不在迁移时截断。

## 学习页与主流程

首屏继续显示实际词表，任务入口为“新词 / 到期复习”。新词顶部显示当前词书与第 N 单元，切换后词表和标题一起更新；复习顶部显示“全部词书 / 到期复习”，隐藏单元和词书选择器。

标签数量分别表示本单元未学新词和全词库当前到期词，任务进度按固定分组的提交情况显示。新增到期词及本次已提交后再次到期的词单独提示，不改变正在检查的词表。复习计划的“继续本次复习”优先恢复当前位置；若当前位置已提交，则进入第一组未完成任务。全部完成且无到期词时，明确提供“学习新词”入口。

默认入口顺序为：继续未完成任务、开始到期复习、学习新词、展示完成情况。用户可主动选择新词或自由练习。完成一组后显示结果与下一组入口，由用户继续，避免突然跳页。

一次正式学习经过以下步骤：

1. 生成任务，固定本组词条及顺序。
2. 遮义回想，点按不熟词记录本轮忘记。
3. 展开释义核对，按需查看发音、例句或助记。
4. 点击“本组已检查完”，确认其余词已经自测记住。
5. 保存结果并安排下次复习，再展示下一组入口。

例如一组有 20 词，用户标出 5 个不熟词，提交前显示“不熟 5 词，其余 15 词；提交表示其余词已经自测记住”。其余词在提交前保持待确认状态，系统不把浏览、滚动或停留时间当成已经记住的证据。

“看词”用于查看内容和调整标记，“自测”提供正式提交入口。自测先回想，按需展开释义核对，并可在核对行直接标记或取消不熟。自由练习允许提前回看，保留练习反馈，不提前推进正式复习阶段。

“看词 / 读短文 / 自测”始终使用同一任务。读短文即语境记忆，使用当前固定组的全部词条，文章按任务 ID 和组号缓存。读文章、看译文和查词均不更新成绩；“进入本组遮义自测”切回原组并隐藏释义，随后正式提交。新词与到期复习共用此规则。看词和自测的切换以一次保存同时更新任务与显示方式，避免界面与保存状态脱节。

原有短文改名为“阅读 -> 自选词短文”，使用独立单元浏览位置，不改变学习任务。其保存内容与当前组目标词完全一致时，可在语境记忆中复用。阅读页另提供回到当前组语境记忆的明确入口。

## 标记与提交规则

| 操作 | 保存的变化 | 是否更新复习计划 |
| --- | --- | --- |
| 自测中标为不熟 | 本轮忘记，以及本轮对应的标记增量 | 提交前不更新 |
| 本轮重复点按同一不熟词 | 保留结果，同一轮仅增加一次标记 | 不更新 |
| 详情中手动调整六点 | 调整关注程度 | 不更新 |
| 提交本组 | 确认本轮结果、追加学习记录、更新到期时间 | 更新 |
| 标为熟词 | 暂时移出学习队列，保留历史 | 不伪造复习成绩 |
| 中途退出 | 保存草稿和位置 | 不更新 |

自测草稿记录本轮是否已应用标记增量，恢复或保存重试不会重复增加。取消本轮“不熟”时仅回退该操作自身的增量，保留此前标记和后续独立编辑；达到六级时仍保存新的忘记结果。

提交前重新检查词条是否仍存在、是否已标熟、复习状态是否被其他操作改变。标熟或删除的词保留当前页面占位并说明状态，提交时跳过；其他冲突保留草稿，提示重新加载，不覆盖较新的记录。

## 任务生成与中断恢复

正式复习统一使用每个词的实际到期时间。默认保持现有固定间隔方案，FSRS 作为可选方式。切换方案不重排现有到期日期，新的正式提交按当前选择生效；自由练习不改变计划。

词书 Day 保持既有分组。旧 List 的按序号回看可通过自由练习完成。每天少学一点只影响实际进度，原 Day 和历史词序保持稳定。

新词任务从当前 Day 中选择尚未正式学习且未标熟的词；在其他词书中已经学过的共享词按现有记忆状态进入复习，不重新算作新词。Day 的原始目录仍完整保留，用户可以查看或自由练习其中全部词条。

任务生成时固定词条 ID、顺序、来源、类型和分组。本组学习期间新增的到期词等待下一组处理，词条的释义等内容仍读取当前版本。若含义发生修改，需要重新检查该词后再提交。

新词任务按“词书 ID + 单元序号”分别保存，当前任务放在 drafts.learn，其余未完成任务放在 parked。切换单元会保存原任务并恢复目标单元任务，最多保留 200 份停放任务，达到上限时提示先完成已有任务。到期复习只有一份全词库任务；新到期词不会插入正在检查的组。同一单元内重新开始仍须明确结束原草稿，已提交结果保留。

关闭应用、切换页面或断网后，应恢复已保存草稿的任务类型、词表、分组位置与结果。标记与对应草稿作为同一次保存写入；保存失败时显示未保存状态，保留界面中的结果并提供重试，不能展示已经保存，也不能承诺强制关闭后仍能恢复未写入的数据。

停学后保留到期任务，按组处理；用户可以暂停当天新词。同一个词无论来自几本词书，均只有一份记忆状态和一次队列安排。第一版的单词记忆目标为识别词义；未来听写等能力另记结果，不直接覆盖这份记忆状态。

## 完成与统计

| 指标 | 口径 |
| --- | --- |
| 今日新学 | 当天首次正式完成学习的去重词条数，忘记结果也算完成了首次检查 |
| 今日复习 | 当天正式提交复习的去重词条数，含新词到期后在当天再次复习 |
| 待复习 | 当前已到期、已开始学习且未标熟的去重词条数 |
| 熟词 | 用户主动标熟的词条数 |
| 词书已学 | 本书词条中有首次学习依据的数量；熟词另列 |

新学和复习可能包含同一个词，二者不能直接相加作为当天学习的去重总词数。自由练习另记活动，不计入正式新学或复习完成数。日期按用户设备本地日期归属，保留原始时间便于后续核验。

某个 Day 的首次学习完成度与今天的复习完成度分别计算。重新忘记、增加标记或跨书学习不会抹掉已学习的事实。手动跳到后面的 Day 不补记前面 Day 的完成记录。

## 代码与存储职责

继续采用现有 React、Capacitor 与 SQLite。先在现有项目内划清业务模块，保持一次本地保存的完整性。

| 职责 | 内容 |
| --- | --- |
| 生成任务 | 从词书和统一复习队列选词，生成稳定任务与分组 |
| 保存过程 | 保存任务位置、当次结果和对应标记变化 |
| 提交结果 | 校验任务和词条状态，确认成绩、追加记录并保存完成凭据 |
| 安排复习 | 依据提交结果和选定算法计算下次时间 |
| 页面交互 | 展示上述状态、接收操作、显示保存错误和结果 |

任务生成、提交、撤销及统计由 `study.ts` 的纯函数处理；`study-state.ts` 校验草稿、凭据与引用。算法和旧数据迁移沿用 `model.ts`，`App.tsx` 协调完整状态保存、响应核对及失败重试。旧 List 辅助函数暂保留用于历史行为兼容测试，正式学习页已停止使用。

每组具有稳定的提交标识。学习记录、到期时间、完成凭据与草稿推进需要原子保存；收到同一标识的重试应返回已保存结果。现有 revision 校验继续负责防止旧状态覆盖新状态，不能仅靠按钮禁用保证不重复提交。

撤销上一组时回退该组实际造成的记录、到期状态和进度，恢复可继续的草稿。撤销状态需持久保存，旧请求重试不能重新应用被撤销的提交；用户再次提交时使用新的提交标识。若后续独立修改使回退不再安全，应保留现状并说明原因。标记撤销与整组提交撤销各自只影响对应动作。

## 旧数据兼容

迁移保留词条 ID、词书顺序、Day 分组、标记、熟词和现有到期日期。旧数据没有当次草稿时，从没有进行中任务开始，不推断用户刚才检查过什么。

旧记录中的最早复习时间只能作为最早可证实的学习时间，不能保证是真实首次学习日期。旧复习记录、完成标记或卡片次数可作为“历史已学”的依据，迁移不把这类词补记为当天新学；只有有明确首次学习依据的记录才进入对应日期的新学统计。不同依据需要可区分。

新草稿和学习记录字段纳入本地 JSON 备份及手动云端备份；AI 密钥继续独立。导入备份时校验任务引用，已删除词条等失效引用需要可解释地处理，不能因草稿异常清空有效学习数据。

实施时同步检查客户端、Node 服务、Android 原生桥接和云端的格式校验及大小限制。升级数据格式与接口能力标识，确保旧服务或旧客户端不能静默丢弃新字段。整组提交不依赖联网或 AI。

当前本地格式为 v3，API 为 v7。v1/v2 记录迁移时补齐 parked、method 与 contextStories；若旧选择器与新词草稿来源不一致，将原草稿停放到其所属单元，不丢弃。Node、Android 和云端源码均拒绝 v3 降级覆盖，线上服务升级状态见 README。

## 实施顺序与验证

| 顺序 | 交付内容 | 必要验证 |
| --- | --- | --- |
| 1 | 明确数据含义，增加草稿和迁移逻辑 | 旧备份往返、日期和词序保持、异常草稿隔离 |
| 2 | 接通草稿保存、恢复与幂等提交 | 中断续学、重复提交、失败重试、撤销与冲突保护 |
| 3 | 学习页接入新流程，统一复习队列 | 新词与复习切换、跨书去重、任务稳定、自测提交含义 |
| 4 | 完成统计与发布核对 | 新学复习口径、断学续接、网页及 Android 存储一致性 |

每阶段完成直接相关的检查后再进入下一阶段。页面变更核对实际桌面和手机布局、触控与返回路径；Android 检查沿用 [README 中的专用模拟器要求](../README.md#开发与检查)。

贯穿场景：用户开始 20 词，标出 5 个不熟词，中途退出；重启恢复并提交，5 词进入重学安排，其余词正常排期。到期后复习，第二天停学，第三天返回时任务仍在。切换词书后已学记录和待复习词仍能接续；重复提交、保存失败和撤销均不丢失或重复记账。

本轮范围为可靠背词流程、单元切换和同组语境记忆。核心释义校对、阅读内容扩充、听力练习和 AI 文章质量分别推进，通过同一词条 ID 衔接本模块。
